# SQL Injection

SQL Injection은 외부 입력이 SQL 쿼리의 일부로 해석되어 데이터베이스가 애플리케이션에서 의도하지 않은 명령을 실행하는 취약점이다.

## 취약점 발생 원인

애플리케이션이 요청값을 SQL 문자열에 직접 붙이면 데이터베이스는 입력이 포함된 전체 문자열을 하나의 쿼리로 해석한다. 이때 외부 입력이 SQL 구문으로 해석되면 조회 조건이 달라지거나 기존 조건의 일부가 주석으로 처리될 수 있다. 연결에서 다중 SQL 문 실행을 허용하는 경우에는 추가 명령이 실행될 수도 있다.

## 공통 방어 방법

- **값 바인딩**은 SQL 구조를 코드에서 정하고 요청값을 별도 파라미터로 전달하는 방식이다. 세미콜론이나 주석 표기가 포함된 입력도 하나의 값으로 처리되며 쿼리 구조는 유지된다.
- **입력값 검증**은 요청의 필수 여부, 타입, 길이와 허용 범위를 확인한다. 검증을 통과한 값도 데이터베이스에 전달할 때 바인딩한다.
- **허용 목록**은 컬럼명, 테이블명, 정렬 방향처럼 값으로 바인딩할 수 없는 SQL 구조에 적용한다. 요청 키를 애플리케이션에 정의된 항목에 매핑하고, 등록되지 않은 키는 거부한다.
- **최소 권한**은 애플리케이션 계정으로 접근할 수 있는 범위를 제한한다. 조회 계정에는 필요한 테이블이나 뷰의 `SELECT` 권한을 부여하고, 스키마 변경에는 별도 계정을 사용한다.
